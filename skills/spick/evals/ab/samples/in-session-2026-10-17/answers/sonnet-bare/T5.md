**一、备份范围**
- 必备份：~/dev 下的源码（靠 Git 远端为主，本地备份兜底未提交改动和 .git）、文稿目录、各机配置（dotfiles、~/.claude、SSH/GPG 密钥）、Obsidian 库。
- 排除：node_modules、target、构建产物、缓存、系统与应用本体（可重装）。
- 密钥和钥匙串导出单独加密备份，不混入普通数据。

**二、频率**
- 每日一次增量，夜间或开机后自动触发，错过则补跑。
- 每小时对 ~/dev 做轻量快照，覆盖当天误删。
- 保留策略：日备 14 份、周备 8 份、月备 12 份。

**三、存储位置（3-2-1）**
- 本地：家中 NAS 或外置盘，作为主备份仓库。
- 异地：加密后上传云对象存储（如 B2/S3 类），客户端加密，云端只见密文。
- 工具统一用 restic 或 Kopia，Mac 与 Windows 共用同一仓库格式，自带去重、加密和快照。
- 调度：Mac 用 launchd，Windows 用任务计划程序，配置模板放同一份文档里。

**四、恢复演练**
- 每月抽查：随机还原一台机器的一个项目，核对文件哈希和 git status。
- 每季度整机演练：用空盘或虚拟机从零恢复，计时并记录缺口。
- 每次备份后自动跑仓库校验，失败时推送通知，不能只靠无报错。

**五、风险与取舍**
- iCloud 与 git 双重同步会损坏仓库，所以备份工具只读源目录，仓库不放在 iCloud 内。
- 备份软件与被备份数据同在一处会一起丢，因此必须有异地副本。
- 勒索或误删会同步到备份，需启用快照不可变或版本保留，并让备份凭据与日常账号分离。
- 密码丢失意味着数据永久不可读，口令要离线存两份。
- Windows 与 macOS 文件名大小写、权限、换行符不同，恢复时可能出现差异，演练时要覆盖。
- 取舍：每日增量成本低，但最多丢一天数据，小时快照用来补足这一缺口。云端容量和费用随历史增长，靠保留策略控制。
