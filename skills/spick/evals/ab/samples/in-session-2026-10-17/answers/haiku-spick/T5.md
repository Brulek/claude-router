结论：代码靠 GitHub 远端，资料靠脱离 iCloud 的版本化快照；最大风险是 iCloud 把误删或损坏同步到所有机器。

一、备份范围
- 代码：~/dev。GitHub 只保存已推送的提交；未推送分支和本地笔记要靠文件级备份。
- 资料：~/Documents、Obsidian 库、~/claude-sync。
- Windows：用户目录。
- 排除 node_modules、target 等可重新生成的产物。

二、频率
- 每小时：Time Machine 本地快照。
- 每日夜间：异地增量快照；收工前推送 wip 分支。
- 每月：异地全量校验。

三、存储位置
- 本地：每台 Mac 配一块外置盘（本机尚未配置 Time Machine）。
- 异地：主 Mac 用 restic、Arq 这类加密工具推到对象存储，并关闭"优化 Mac 存储"，避免只备份到占位文件；Windows 用"文件历史"加同类工具。
- iCloud 只是同步，不算备份。

四、恢复演练
- 每月抽一个项目还原到临时目录，核对校验和并跑一次构建。
- 每季度模拟丢一台机器，从零还原，记录耗时。

五、风险与取舍
- 资料只从主 Mac 备份，省掉重复上传；代价是主机离线就会断档，需要监控"上次成功时间"。
- git 仓库不放进 iCloud。
- 待你拍板：对象存储选哪家、预算多少，加密口令由谁保管。
