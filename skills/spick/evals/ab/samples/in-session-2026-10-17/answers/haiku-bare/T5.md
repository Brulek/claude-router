一、备份范围
- Mac（多台）：~/dev 下全部代码仓库，含 .git 目录与未推送的改动；~/Documents 中的非代码资料。代码不放 ~/Documents，避免 iCloud 与 git 双重同步损坏仓库。
- Windows：项目目录及其 Git 仓库。排除 node_modules、target、build 等依赖与构建产物。

二、频率
- 代码：每日一次增量快照；每次工作结束时 git push 到 GitHub 私有仓库。
- 资料：每日一次增量，保留最近 30 份日快照，并每周保留一份长期快照。

三、存储位置
- 主份：本地外置硬盘，按日增量，用硬链接去重。
- 异地：加密后上传至云端对象存储或 NAS，由一台机器汇总。
- 第二副本：GitHub 私有仓库承载代码。

四、恢复演练
- 每月一次：随机挑一个仓库和一份资料，在临时目录还原并比对校验和。
- 每季度一次：全量恢复，记录耗时与缺失项。

五、风险与取舍
- iCloud 同步不等于备份：误删会同步扩散，不能替代快照。
- 加密密钥丢失则备份全部不可用，需离线保存一份密钥副本。
- Windows 与 macOS 的路径、换行与大小写差异，可能导致恢复后不一致，演练时需专门核对。
- 带宽与云存储成本有限，取舍为日增量、周全量，接受单日改动可能丢失。
