结论：rotate_b.sh 出错处理更健壮。

理由：
1. 参数校验：b 检查参数个数，并确认 KEEP_DAYS 为纯数字；a 只检查非空。
2. gzip 失败：b 删除半成品、以 74 退出且保留原日志；a 仅靠 set -e 退出，没有专门提示。
3. 文件名安全：b 用 while read 处理并给 rm 加 --；a 的 $(find) 在含空格的文件名上会词分割出错。
4. 删除失败：b 逐个检查并报告；a 的 ((removed++)) 在 removed 为 0 时返回非零，配合 set -e 可能在首个删除后提前退出（由代码推断，未实际运行）。

b 的不足：未使用 set -e，日志清空与 find 失败均未检查。
