结论：rotate_b.sh 在出错处理上更健壮。

理由：
1. rotate_a.sh 用 `set -e`，但清理循环里的 `((removed++))` 在 removed 为 0 时返回非零，脚本在删除第一个归档后就退出（退出码 1），不会删完其余归档，也不打印汇总。我在临时目录实测：三个过期归档只删了一个，退出码 1；rotate_b 删除全部三个，退出码 0。
2. rotate_a 的 `for old in $(find ...)` 按空白拆分文件名，文件名含空格时会出错。
3. rotate_b 对每种失败都有明确检查和退出码（用法 64、非数字保留天数 64、日志不存在 66、建目录失败 73、gzip 失败 74）。gzip 失败时删除半成品并保证原日志不被截断。单个归档删除失败只报错并继续。
4. rotate_a 依靠 trap 和 set -e 间接处理错误，其中 `mv` 与 `: > "$log"` 的失败是靠隐式行为兜底。

rotate_b 的不足：`: > "$log"` 的截断没有检查结果，失败时仍会打印“rotated”。
