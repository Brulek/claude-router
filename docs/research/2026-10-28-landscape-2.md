# Landscape 2: routing and delegation tools for Claude Code (2026-10-28)

A second pass over comparable open-source projects, eleven days after the first ([2026-10-17](2026-10-17-landscape.md)).
That doc covered seven projects; this one covers twenty-nine new ones, found by web search on 2026-10-28 and read
through their README plus one or two key files each (hooks, benchmark reports, policy pages). The GitHub API was
blocked from the session, so stars and dates are what the rendered pages showed; "last commit" is the newest date on
the commits page. Numbers are the authors' claims unless marked. One repo (qtnx/qtnx-claude-plugin) returned 404 and
is dropped.

The posture is learning, not ranking. Several of these projects are smaller than spick and have no users; several
measured something spick has not. Both kinds taught something.

## The field in one paragraph

The field has split into four shapes. (1) **Main-model switchers** rewrite the session's model and effort per turn
through the new function-hook / mod API (`prompt.submit`, `turn.step`). (2) **Pinned-subagent routers** keep the main
model and send work to agents whose frontmatter pins model and effort, with a hook on `Agent` to enforce. (3) **Effort
routers** keep one model and vary effort. (4) **Multi-CLI delegators** hand tasks to Codex, Gemini, Cursor, Copilot or
local models. Spick is a (2) with a Haiku main session plus a (4) with a lane registry. Almost everyone now treats
effort as a routing output; almost nobody enforces outcomes (did a test run, did a review produce a report) the way the
spick mod does; and the three controlled measurements published this month all found that delegating to a subagent
costs more in a short session.

## What the cluster collectively says (new since 2026-10-17)

1. **Delegation costs more in a short session, measured three times.** snowu +23 to +84% on fresh-session chores,
   AqueGen +52% on a small fixture and +23% on a 12-stage pipeline, NawkaRouter's $0.10–0.25 cold-cache tax per
   Sonnet/Opus subagent, pctan88's bulk reading +20%. The saving, where found, came from a cheaper main model (snowu),
   a Haiku pin (AqueGen −9%), or a long session. This is principle 2 (not dispatching is the default) with numbers, and
   it supports Haiku-main more than any of spick's own evals did.
2. **Context is the bill.** jknack0: 93% of 30-day spend was context, 7% output. Jfri3ss: one session re-read 506M
   tokens; tool output was under 1% of it. snowu: the same PR cost 4× in a 106k session. Routers are drifting toward
   context management (`/clear` hints, context warnings, brief-size caps, output guards) and away from model choice.
3. **Main-model switching is being tried again through the mod API, and its own authors document the cache loss.**
   DuffyEthan's break-even code comment, hhchuan89's warm-cache exception, budget-router's `cacheWarmMinutes`,
   misterkante's `minTurnsBetweenSwitches`. Principle 8 holds.
4. **Effort now has data.** NawkaRouter: low effort is dominated, medium is the floor, max never pays; titouannwtt
   denies Sonnet low and Opus max; tzachbon routes effort first on one model. Spick's effort table was written from
   judgement; the `coder` low row deserves a check.
5. **Enforcement has moved to dispatch time.** `PreToolUse(Agent)` hooks now default, strip, cap or refuse models and
   efforts (abroberts14, DevstateBelgium, titouannwtt, NawkaRouter, token-economy, younesbag). Spick enforces at edit
   time and stop time but not at dispatch time; the two are complementary.
6. **Escalation carries the evidence up.** `ESCALATE: <reason>` replies (NawkaRouter, agent-router), misterkante's
   `--escalate` feeding the failing output into the next tier, vimoxshah's failure log, hhchuan89's consecutive tool
   errors. And one strong result against cheap-first debugging: misterkante's Sonnet-first then Opus cost +37% over
   Opus direct, which is spick's own round-3 finding reproduced by someone else.
7. **Benchmark hygiene is ahead of spick in one repo.** agent-router: blind labels by a non-author, frozen hashed
   inputs, dev/holdout split, a calibrator that proposes and never writes. AqueGen keeps a correction log and frozen
   logs. snowu caps each run's budget and separates fresh from long-session cells.
8. **A delegate's "done" is distrusted everywhere now, by different means.** pctan88 returns diff plus test log,
   cc-multi-cli returns a Verification block, OpenAI's rescue returns raw stdout, ehnruiz proves the test fails on
   pre-fix code. Spick's stop-time check that a review call produced a report is the only harness-level version of
   this in the set.
9. **Vendor churn kills integrations.** The 999-star delegator died when Codex removed `mcp-server`. Survivors use a
   thin shell shim per vendor and refresh model catalogs by live calls. Spick's wrapper is in the resilient camp and
   lacks only a recorded "last verified against vendor version X" per lane.
10. **Learning loops are appearing, unvalidated.** jknack0 (Wilson lower bound ≥ 0.8, n ≥ 8), DevstateBelgium (three
    consistent rows then an explicit push), budget-router (federated prior), ValhalaStudio. None publishes an outcome.
    Spick's turn record is the input such a loop would need; the bar (a statistical threshold, an explicit push) is the
    part worth copying before the learning.

## What spick should take from this

Ordered by expected value over cost, each a hypothesis for the turn record to test, not a decision.

1. **Add a dispatch-time check to the mod** (`PreToolUse` on `Agent`): refuse `effort: max` unless the user said
   "extremely important"; warn on a brief under a minimum length; refuse a Haiku `coder` brief that names auth, money,
   schema or deploy. Cheapest moment, on facts; mirrors the edit cap. (titouannwtt, NawkaRouter, token-economy)
2. **Report derived rates in `/spick audit`**: share of tokens below the session tier, tier-leak rate for unpinned
   dispatches, cold-start tax per delegate (its cache-write tokens), and a fresh-vs-long-session split. The record
   already holds the inputs. (AqueGen, snowu)
3. **Regression proof for a failing-test bug**: when `coder` fixes a bug with a test, the Evidence block states that
   the test failed on the pre-fix tree (a scratch worktree) and passes after. (ehnruiz)
4. **Protect the gate's own inputs**: the edit cap should count edits to `spick.json`, the hook files, and test/lint
   config as source, so a check cannot be passed by loosening it. (ehnruiz config-protection)
5. **Re-check the effort table against data**: NawkaRouter found low dominated; spick allows `coder` low for
   mechanical edits. One eval cell settles it.
6. **A per-lane "verified against" field** in the lane registry (vendor CLI version and date), shown by `spick doctor`
   when stale, and a depth guard so a delegate cannot delegate onward. (mateusz-klatt)
7. **Rationale beside the rules**: a `rules.json` row gains an optional `why` with the source and date, rendered into
   `providers.md`; and a re-ranking protocol for model releases (keep one known-answer task per tier, re-run, move a
   boundary only on two identical failures). (thevrus)
8. **Benchmark hygiene for the next eval round**: blind labels, frozen inputs with a hash, a holdout split, every
   cell with its n. (agent-router, AqueGen)
9. **Compaction as a routing event**: the hint line already re-arrives per prompt; check that the mod's turn state
   and the `Kept:` rule survive compaction and `/clear`. (younesbag, vimoxshah)
10. **Context is the bill**: consider an output guard on large `Read`/`git diff`/test output with rule IDs and an
    override, and report its per-rule saving. Lower priority than the above because spick's Haiku-main already keeps
    the context small, and the 80k warning exists. (Jfri3ss, jknack0)

Not taken, with reasons: per-turn main-model switching (its own authors measured the cache loss); a budget that refuses
prompts at 100% (a hard stop in the user's workflow is theirs to choose, and spick's quota line already informs); a
hosted third-party research gateway (supply chain); banning Haiku (no data behind it, and the measurements here favour
Haiku pins); a Stop-hook review gate that reruns review on every stop (OpenAI's own README warns of the loop).
